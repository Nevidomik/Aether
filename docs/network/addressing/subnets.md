# Адресний план

## Мета

Зафіксувати відомі підмережі, адреси керування та невизначені параметри.

## Архітектура

Використовуються зовнішня Wi-Fi мережа, внутрішня мережа полігону, окрема мережа керування WDS-мостом і Tailscale overlay.

## Передумови

- доступ до таблиць DHCP;
- актуальні `ip route` та `/ip address print`;
- перелік VM і мережевих пристроїв.

## Конфігурація

### Підмережі

| CIDR | Призначення | Стан |
|---|---|---|
| `10.192.0.0/21` | Зовнішня мережа `Nuwm` | Керується зовнішнім DHCP |
| `192.168.0.0/24` | Керування TP-Link | Локальна службова мережа |
| `192.168.100.0/24` | Внутрішня мережа полігону | Активна |

### Відомі адреси

| Адреса | Компонент | Спосіб призначення |
|---|---|---|
| `10.192.7.254` | Шлюз `Nuwm` | Зовнішня мережа |
| `10.192.1.253` | USB Wi-Fi Proxmox | DHCP, за знятим станом |
| `10.192.2.75` | WAN MikroTik | Приклад DHCP-адреси, не фіксувати як постійну |
| `192.168.0.1` | TP-Link | Статично |
| `192.168.0.2` | MikroTik `ether1-WAN` | Статично |
| `192.168.100.1` | MikroTik `bridge-LAN` | Статично |
| `192.168.100.196` | Proxmox `vmbr0` | Статично |

Адреси Ubuntu VM не надані й потребують інвентаризації.

## Покрокове налаштування

1. Зібрати фактичні адреси всіх VM.
2. Визначити DHCP-пул та діапазон статичних адрес.
3. Усунути дублікати й зарезервувати інфраструктурні адреси.
4. Зафіксувати єдиний шлюз і DNS для кожної мережі.

## Перевірка

Звірити таблицю з ARP, DHCP leases, конфігураціями Proxmox і MikroTik.

## Troubleshooting

| Симптом | Можлива причина | Рішення |
|---|---|---|
| Конфлікт IP | Адреса присутня в DHCP-пулі | Виключити статичні адреси з пулу |
| Адреса WAN змінилася | DHCP у зовнішній мережі | Не використовувати її як постійну |
| VM не знаходить DNS | Неправильний DNS або gateway | Перевірити мережеву конфігурацію VM |
