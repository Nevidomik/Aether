# Віддалений доступ через Tailscale

## Мета

Забезпечити контрольований віддалений доступ до мережі керування кіберполігону.

## Архітектура

Proxmox налаштований як Tailscale Subnet Router і анонсує `192.168.100.0/24`. Маршрут схвалено в адміністративній панелі Tailscale.

## Передумови

- обліковий запис організації Tailscale;
- Tailscale встановлений на Proxmox;
- IPv4 forwarding увімкнений;
- ACL або grants для адміністраторів;
- схвалення subnet route.

## Конфігурація

| Параметр | Значення |
|---|---|
| Subnet router | Proxmox |
| Анонсований маршрут | `192.168.100.0/24` |
| Схвалення маршруту | Увімкнено |
| Закінчення строку ключа | Вимкнено за наданим описом |

Вимкнення строку дії ключа підвищує вимоги до контролю облікового запису, MFA, ACL і регулярного перегляду пристроїв.

## Покрокове налаштування

1. Увімкнути IP forwarding.
2. Авторизувати вузол Proxmox у Tailscale.
3. Анонсувати `192.168.100.0/24`.
4. Схвалити маршрут в адміністративній панелі.
5. Обмежити доступ ACL лише адміністративними ролями.
6. Перевірити доступ до кожного дозволеного компонента.

## Перевірка

На віддаленому клієнті перевірити маршрут і доступ до Proxmox та MikroTik. Окремо перевірити, що неавторизований користувач не має доступу до підмережі.

## Troubleshooting

| Симптом | Можлива причина | Рішення |
|---|---|---|
| Маршрут відсутній | Його не схвалено або клієнт не приймає routes | Перевірити налаштування адміністратора й клієнта |
| Вузол доступний, LAN — ні | Вимкнено forwarding або firewall блокує | Перевірити sysctl і FORWARD chain |
| Доступ надто широкий | ACL не обмежують subnet route | Уточнити групи та дозволені порти |
