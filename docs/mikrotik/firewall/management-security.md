# Безпека керування MikroTik

## Мета

Мінімізувати доступні служби керування та обмежити адміністративний доступ довіреними мережами.

## Архітектура

Керування MikroTik виконується з внутрішньої адміністративної мережі або через Tailscale. WAN не повинен приймати запити керування.

## Передумови

- резервний export MikroTik;
- перевірений локальний або консольний доступ;
- визначений список адміністративних адрес;
- наявні базові правила established/related і drop invalid.

## Конфігурація

Непотрібні служби вимикаються:

```routeros
/ip service disable api,api-ssl,ftp,ssh,telnet,www,www-ssl
```

За наданою конфігурацією залишається Winbox. Його дозволені адреси необхідно обмежити адміністративною підмережею; точний список слід визначити після сегментації.

Доступ до перенаправлення TP-Link на `8080/tcp` також має бути дозволений лише адміністраторам.

## Покрокове налаштування

1. Перевірити доступ через Winbox з довіреного вузла.
2. Визначити адміністративні IP або address list.
3. Обмежити Winbox параметром `address`.
4. Дозволити керування в chain `input` лише з довірених джерел.
5. Заборонити решту вхідного трафіку після службових дозволів.
6. Перевірити доступ до TP-Link port forward.

## Перевірка

```routeros
/ip service print
/ip firewall filter print stats
/ip firewall nat print stats
```

Перевірити, що керування доступне з адміністративного вузла й недоступне з WAN та студентських сегментів.

## Troubleshooting

| Симптом | Можлива причина | Рішення |
|---|---|---|
| Winbox недоступний | Надто вузький список адрес | Використати локальний MAC Winbox і виправити список |
| Служба знову активна | Конфігурацію змінено або відновлено | Перевірити журнал і повторно застосувати baseline |
| TP-Link доступний усім LAN-клієнтам | Немає обмеження dst-nat | Додати source address list до правила |
